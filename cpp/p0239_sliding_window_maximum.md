# 239. Sliding Window Maximum · C++17

[原题](https://leetcode.com/problems/sliding-window-maximum/)要求按窗口从左至右返回每个长度为 k 的连续窗口最大值。输入长度 n 为 1..100000，元素在 -10000..10000，且 1<=k<=n。接口为 `Solution::maxSlidingWindow(vector<int>& nums, int k)`，本实现保持 nums 不变。

用双端队列保存候选的下标，下标递增、对应数值严格递减。处理右端点 right 时先删掉所有 `index<=right-k` 的过期队首；新的窗口从 `right-k+1` 开始，这个等号不能省略。然后从队尾删除数值不大于新值的候选，再追加 right。只有 `right>=k-1`、窗口完整后才输出队首对应值。

删除队尾是安全的：设旧下标 i 小于新下标 j，且 nums[i]<=nums[j]。当前及未来任何还包含 i 的窗口也会包含 j（在 j 已加入且 i 尚未过期的期间），因此旧值不会比新值更好；j 还会更晚过期。等值时保留较新的下标，避免用已过期的相同值支撑后续窗口。用下标存队列可以同时判断有效期和读取数值。

处理完一个位置后的不变量是：队列所有下标都在当前有效范围内且递增，数值严格递减；任何已处理但不在队列的有效元素，都被某个更晚且不小于它的有效候选支配。过期删除不会破坏后者，因为支配者比被支配者更新，不可能更早过期；尾部删除后可以把支配关系继续传给新值。因此队首数值是整个有效窗口的最大值。对每个完整窗口恰好输出一次，共 n-k+1 项。

例如 `[9,1,1]`、k=2，前两个值的最大值是 9；right=2 时必须先删掉下标 0，第二个答案为 1。不能仅保持队列数值有序却遗漏有效期。`[4,4,1]`、k=2 中新 4 替代旧 4，两个窗口都得到 4；全负数组的最大值也必须来自输入，不能用默认 0 作为答案。

把过期与等值替换放在同一条轨迹里：输入 `[9,4,4,1,3,0]`、k=3。下表记录处理完 right 后的队列，条目为 `下标:值`，答案依次是 `[9,4,4,3]`。

| right | 本步删除 | 剩余候选 | 完整窗口最大值 |
| --- | --- | --- | --- |
| 0 | 无 | `0:9` | 窗口未满 |
| 1 | 无 | `0:9, 1:4` | 窗口未满 |
| 2 | 尾部 `1:4` 被更晚的等值替换 | `0:9, 2:4` | 9 |
| 3 | 队首 `0:9` 过期 | `2:4, 3:1` | 4 |
| 4 | 尾部 `3:1` 被新值支配 | `2:4, 4:3` | 4 |
| 5 | 队首 `2:4` 过期 | `4:3, 5:0` | 3 |

这里 right=3 时下标 1 已被丢弃，但较新的等值下标 2 仍有效，所以仍能给出 4；right=5 时下标 2 恰到过期边界，答案才变成 3。

每个下标入队一次，最多从某一端删除一次。整个双层循环的总工作量为 O(n)。队列至多保存 k 个有效候选，辅助空间 O(k)，另有 O(n-k+1) 的结果空间。下标和 right-k 都在 int 范围内；元素只比较、不求和，不涉及高度累积或数值溢出。

还有两类可独立验证的性质。记窗口最大值序列为 M(nums,k)，将输入反转后，原窗口 `[j,j+k)` 映射到反转输入的 `[n-j-k,n-j)`，窗口内元素相同，只是方向改变。因此输出下标 j 映射到 `n-k-j`，有 `M(reverse(nums),k)=reverse(M(nums,k))`。这不要求队列中间状态也反转，只约束最终答案。

对严格递增变换 `f(x)=a*x+b`、a>0，任意窗口内元素的大小关系保持，故 `max(f(window))=f(max(window))`。于是 `M(f(nums),k)=f(M(nums,k))`。只在变换后的元素仍处于合法范围时使用此性质；负比例会颠倒大小关系，不能套用同一个最大值等式。

测试 oracle 对每个窗口直接调用区间 `max_element`，用 O(n*k) 的直接扫描得到答案，不复用候选队列。穷举长度 1..8、取值 `{-2,0,3}` 的全部 9840 个数组，对每个合法 k 检查，共 73812 个窗口参数查询。每次同时核对输出项数及输入保持。十一个手算用例覆盖上表、过期边界、重复最大值、负数、单调序列、k=1和k=n、数值端点。

每个穷举查询还检查一次反转，以及 `(a,b)=(1,-13)、(1,17)、(2,0)、(2500,0)` 四种变换。期望从原输入的独立扫描答案反转或变换得到，共 73812 次反转、147624 次平移和 147624 次正比例缩放检查。原小数组取值仅 -2、0、3，即使乘 2500 也只落在 -5000..7500；测试同时断言变换后的输入合法。大型及数值端点用例保留原值，不对其盲目缩放。

六个大型边界包括：长度 100000、以 -10000..10000 为周期的输入，k=20001 时每个窗口恰覆盖完整周期，80000 个输出均为 10000；同一输入分别取 k=1 和 k=n；长度 100000 的全 -10000 且 k=50000；长度 20001 的递增与递减序列且 k=10000。单调用例分别从窗口末端/首端直接构造期望，避免大型 oracle 的平方扫描。
