# 49. Group Anagrams · C++17

[原题](https://leetcode.com/problems/group-anagrams/)要求把互为字母异位词的字符串分组。接口为`vector<vector<string>> Solution::groupAnagrams(vector<string>& strs)`；不修改输入，组顺序与组内顺序没有额外承诺。官方输入1..10000个字符串，每词0..100个小写英文字母。空列表作为扩展返回空分组；空字符串是合法词，多个空字符串必须保留各自的出现次数。

逐词复制并排序得到键，用unordered_map把键映射到输出组下标。新键的下标是当前groups.size()，先创建空组再把原词追加进去；已有键沿用原下标。map中存的是数字下标，不持有vector扩容后可能失效的元素引用。每次push只追加当前输入的一个词，重复词不会被去重。

字符排序得到同一键，当且仅当每个字符的次数相同：相同次数决定同一非递减字符序列；相同排序序列又能逐项还原各字符次数。处理前t个词后，每个不同键恰好对应一个组，组内恰好含这些词中拥有该键的所有出现。新键建组和旧键追加均保持不变量，最后所有输入出现都被准确分组。只比较字符集合会错误地把ab和aab并入同组，本实现保留次数。

N为词数，L为最大长度。在哈希操作平均常数且字符串哈希/比较按长度计费时，复制、排序与输出合计平均O(N + N L log(L+1))。哈希碰撞最坏不保证这一时间。字典存储不同排序键及下标，额外空间O(N + N L)，单次临时键O(L)已包含在内；返回分组也占O(N + N L)，不能仅把组数当字符存储量。空词仍有每词处理和容器成本，所以保留O(N)项。

独立测试用26频数比较、逐组寻找代表词来形成oracle，不复用生产中的排序键或哈希组索引。枚举8个词构成的长度0..4列表共4681组；按组内与组间排序归一化比较，完整保留重复次数，不把vector误转成set。另有3个固定例子，覆盖空词、同集合不同重数、重复词；边界为10000个长度100的词。每次检查输入保持。

A补写输入["eat","tea","","eat","tan",""]的键与输出账本。组下标由输入中首次遇见键的顺序决定，表格不要求哈希表按此顺序迭代：

| 输入下标 / 原词 | 排序键 | 新键及下标 | 追加后的对应组 |
| --- | --- | --- | --- |
| 0 / eat | aet | 新键，0 | [eat] |
| 1 / tea | aet | 已有，0 | [eat,tea] |
| 2 / 空词 | 空键 | 新键，1 | [空词] |
| 3 / eat | aet | 已有，0 | [eat,tea,eat] |
| 4 / tan | ant | 新键，2 | [tan] |
| 5 / 空词 | 空键 | 已有，1 | [空词,空词] |

两个eat和两个空词均表示不同输入出现，不能去重。新键先以groups.size()为下标登记，再创建这个组；数字下标在groups扩容后仍有意义，若保存组元素引用则不能直接作同样推理。

把每个词的字符次序反转，不改变任何字符的重数，所以原本同组与不同组的关系都保持。返回值应是原分组中每个词也逐个反转后的分组，不能只比较变换前后的字符串是否相等。A对全部4681个小列表、3个固定例子和10000词边界共4685次exact调用加入此性质；逐词反转是可逆映射，保留空词、重复次数、长度与小写字母合同。比较仍对vector组内/组间排序，未用set抹掉重复；原26频数oracle和输入保持检查保留。
